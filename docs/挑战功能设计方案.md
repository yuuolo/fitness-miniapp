# 会员挑战功能 · 设计方案（v2 · 规则待定稿）

> 目标：在「身体数据 / 力量排行 / 竞赛 / 友圈 / 运动记录」之上，加一层**人对人的轻量互动**，
> 让会员有借口互相约练、互相监督，产生复访和话题。
> 原则：**复用现有项目与成绩体系**，不另起一套数据；纯趣味，不涉及钱和实物奖励。
>
> **v2 更新说明**：这份是重新讨论用的版本。系统这半个月变化很大（见第三节），
> 有些原来的假设已经不成立，方案已按现状调整。**规则条款留空待定，等你拍板后再落代码。**

---

## 一、玩法设计

### 1.1 三种挑战形态（分三期）

| 形态 | 说明 | 期次 |
| --- | --- | --- |
| **1v1 指定挑战** | A 指定 B，选一个项目 + 比法 + 期限；B 应战或拒绝 | P1 |
| **公开挑战（悬赏）** | A 公开挂一个成绩，任何会员来"打擂"，先到先得 / 限 3 人 | P3 |
| **团队 / 赛季赛** | 分队累计积分、月度赛季榜 | P3 |

P1 只做 1v1，先把闭环跑通。

### 1.2 挑战要素

发起时选：

1. **项目**：复用排行榜项目（当前 5 个：卧推 / 深蹲 / 硬拉 / 站姿肩推 / 引体向上，管理员可增改）
2. **比法**
   - 绝对成绩：比重量 / 次数
   - 相对体重：成绩 ÷ 体重
   - **（新）也可以比"综合评分"**：现在有综合评分榜了，可以搞"比谁的身体评分涨得多"
3. **期限**：24h / 72h（默认）/ 7 天
4. **一句垃圾话**（≤20 字，可选）

### 1.3 流程与状态机

```
        ┌──────────── 发起人取消（未应战时） ────────────┐
        ↓                                               │
   [待应战] ──应战──> [进行中] ──双方都交成绩──> [已结算：胜/负/平]
      │  │
      │  └──拒绝──> [已拒绝]（发起人可再发，但同对手 7 天冷却）
      └──超时未应战──> [已失效]
```

- 应战后 X 小时内双方各自提交成绩，超时未交判负
- 双方都不交 → 流局，不计胜负
- 结算后可一键发到友圈（现在友圈已支持视频 + 搜索）

### 1.4 成绩怎么来（三条路，全部走现有成绩体系）

| 方式 | 说明 | 现状 |
| --- | --- | --- |
| **用已有最好成绩** | 一键应战，读 `members.best_lift[项目]` | ✅ 数据现成 |
| **现场练一次（教练录）** | 复用 `saveStrength`，可**附视频** | ✅ 力量成绩已经能拍/选视频，且视频会按管理设定自动裁切 |
| **自己录（会员录）** | 会员自己录运动记录 | ✅ 运动记录已对会员开放（但力量成绩仍只有教练能录） |

> 争议处理现成能力：管理员可以**删除**任何一条力量成绩（删完自动重算最好成绩与评分），
> 所以挑战成绩造假被举报，管理员能删。

## 二、趣味性与奖励（纯虚拟）

- **胜负统计**：胜场 / 负场 / 胜率 / **连胜**
- **徽章**（自动颁发，展示在公开资料页）
  - 首胜、三连、五连
  - 「以下克上」：赢了项目排名比自己高的人
  - 「全项目挑战者」：五个项目各赢过一次
  - **（新）「评分狙击」**：赢了综合评分比自己高 10 分以上的人
- **挑战榜**：本周胜场榜、当前连胜榜（可复用排行榜页的 tab 结构）
- 结算后生成一条友圈动态（`type=challenge`），可带现场视频

## 三、这半个月系统变化对本方案的影响（重要）

| 变化 | 影响 |
| --- | --- |
| **评分改成实时计算** | 挑战赢一场后，综合评分立刻变（相对力量/三项合计都会变），所以"挑战 → 影响评分排名"是**实时联动**的，不需要额外处理 |
| **相对力量改成按项数计分** | 1 项 ≤13.3、2 项 ≤26.7、3 项才满分。**所以"补全三项"现在直接等于涨分**——这是做"挑战"最好的理由：拿挑战当"补数据"的钩子 |
| **力量成绩可附视频（自动裁切）** | 挑战现场视频留档成为可能，且复用管理页的上传限制 |
| **运动记录对会员开放** | 挑战项目可以不止力量：可以比"本周跑步距离""连续打卡天数" |
| **视频上传统一限制** | 挑战视频和友圈视频一样，超时长自动裁切 |
| **综合评分榜上线** | 挑战可以直接引用"综合评分"作为比法 |
| **会员搜索统一** | 发起挑战时选对手可直接复用统一的会员搜索 |

## 四、数据模型（草稿，待规则确定后细化）

```sql
-- 挑战（一条 = 一次约战）
create table if not exists challenges (
  id              text primary key,
  challenger      text not null,              -- 发起人 openid
  opponent        text not null,              -- 被挑战者 openid
  lift_key        text not null,              -- 项目 key（来自 lift_items）
  metric          text not null default 'absolute',   -- absolute / relative / score
  trash_talk      text not null default '',
  status          text not null default 'pending',   -- pending/accepted/finished/declined/expired/cancelled
  result          text not null default '',          -- win_challenger / win_opponent / draw / void
  expire_at       bigint not null default 0,         -- 应战截止
  submit_by       bigint not null default 0,         -- 交成绩截止
  created_at      bigint not null default 0,
  finished_at     bigint not null default 0
);

-- 挑战成绩（一场最多两条）
create table if not exists challenge_entries (
  id            text primary key,
  challenge_id  text not null references challenges(id) on delete cascade,
  openid        text not null,
  value         numeric(8,2) not null default 0,
  relative      numeric(8,2) not null default 0,
  weight        numeric(6,2) not null default 0,
  source        text not null default 'best',      -- best / staff（现场录入）/ activity（运动记录）
  video_url     text not null default '',
  created_at    bigint not null default 0
);
```

> 现场录入的成绩仍然写进 `strength_records`（带 `challenge_id` 标记），这样挑战成绩**天然进排行榜**，
> 不搞第二套账。

## 五、接口（6 个新 action）

| action | 权限 | 说明 |
| --- | --- | --- |
| `challengeList` | 会员 | 挑战大厅：`tab=incoming/outgoing/active/history` |

| `respondChallenge` | 被挑战者 | 接受 / 拒绝 |

页面：挑战大厅、发起、详情、挑战榜（4 个新页面）；首页快捷入口加一格「挑战」。

## 六、防滥用（待你确认力度）

| 风险 | 建议对策 |
| --- | --- |
| 刷挑战刷胜场 | 每周最多发起 N 次；同一对手 M 天内只能挑战 1 次 |
| 只挑软柿子 | 「以下克上」徽章只奖励赢排名更高的人；被拒 3 次冷却 24h |
| 成绩造假 | 默认用历史最好成绩（无法伪造）；现场录入必须教练操作，可附视频 |
| 用挑战刷排行榜 | 挑战成绩与普通成绩同源，不额外加权；同一项目每天最多计 1 条挑战成绩 |
| 骚扰 | 被拒绝后不能立刻再发；管理员可取消任意挑战（复用现有删除能力） |
| 拖延 | 应战超时失效；应战后超时未交判负 |

## 七、需要你定的规则（这一版的核心）

### A. 玩法边界

1. **挑战项目**：只用力量项目？还是也允许"运动记录类"（跑步距离、打卡天数）？
   - 建议：P1 只做力量项目（数据最硬），P2 再考虑运动记录
2. **比法**：绝对 / 相对体重 / 综合评分，三种都开，还是只开前两种？
   - 建议：先开「绝对 + 相对体重」；「综合评分」适合做 P2（规则更复杂，容易吵）
3. **是否允许多场同时进行**：每人同时在打的挑战上限？
   - 建议：3 场

### B. 时间与流程

4. **应战期限**：24h / 72h / 7 天，默认哪个？发起时能否自选？
   - 建议：默认 72h，可自选 24h / 72h / 7 天
5. **交成绩期限**：应战后多久内必须交？
   - 建议：48h
6. **超时未交判负，还是直接流局？**
   - 建议：判负（否则有人应战了不交，等于无限拖）
7. **双方都不交**：流局不计胜负 —— 确认？

### C. 成绩来源

8. **会员能不能自己提交挑战成绩**（自己录 + 附视频），还是必须教练录？
   - 建议：必须由教练/管理员录入（现在力量成绩也只有教练能录），会员只能"用已有最好成绩"
9. **用已有最好成绩应战时，成绩是"发起那一刻"锁定，还是"结算时"取最新？**
   - 建议：应战时锁定快照，避免结算前后反复横跳

### D. 输赢与奖励

10. **平局怎么算**：都记 0.5 胜？还是算平局不计胜率？
    - 建议：记平局，不进连胜也不中断连胜
11. **连胜判定**：赢了 +1，输了清零，平局不变 —— 确认？
12. **徽章要不要出现在公开资料页**（别人能看）
    - 建议：要
13. **挑战结果要不要自动发友圈**，还是让会员自己选？
    - 建议：默认不自动发，结算页给「发到友圈」按钮

### E. 防滥用力度

14. **每周发起上限**：3 / 5 / 不限？
15. **同一对手冷却**：3 天 / 7 天 / 不限？
16. **被拒绝几次后冷却**：3 次冷却 24h？
17. **挑战成绩要不要计入排行榜**（同一项目每天限 1 条）？

### F. 范围与节奏

18. **P1 要不要含"挑战榜 + 徽章"**，还是先只做闭环（发起/应战/提交/结算/历史）？
19. **要不要通知**：小程序订阅消息需要模板（个人主体受限），先用页面红点 + 友圈动态顶替？

## 八、我的建议（如果你懒得逐条定，可以直接采用这套）

**P1（先跑闭环，2–3 天）**
- 1v1 挑战，只能用力量项目，比法只开「绝对成绩」
- 应战期限 72h（可自选 24h / 72h / 7 天），交成绩 48h，超时未交判负
- 只能"用已有最好成绩"应战（成绩在应战时锁定），或让教练现场录入（可附视频）
- 结算：胜/负/平；平局不计连胜也不中断
- 每人同时最多 3 场，每周最多发起 5 次，同一对手 7 天 1 次
- 挑战成绩计入排行榜（同项目每天最多 1 条）
- 不做通知，页面红点 + 友圈动态

**P2（玩起来后续上，1–2 天）**
- 挑战榜（周胜场 / 连胜）+ 4 个徽章 + 结算页发友圈
- 比法加「相对体重」

**P3（看热度）**
- 公开悬赏挑战、运动记录类挑战、团队赛季
- 「综合评分」比法

## 九、不做什么（明确排除）

- 不做金钱 / 实物赌注（合规风险）
- 不做实时语音 / 视频对战（用现场视频留档代替）
- 不做复杂排位分 / ELO（对健身会员太重）
- 不新增第二套成绩数据（全部挂在 strength_records 上）

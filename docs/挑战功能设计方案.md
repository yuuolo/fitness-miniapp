# 会员挑战功能 · 设计方案（v3 · 裁判制）

> v3 按你定的规则重写：**必须指定教练当主裁判；教练判胜负平、可标视频作弊；双方各自上传视频；
> 挑战公开可见；会员可以发表意见。**
> 目标：在「身体数据 / 力量排行 / 竞赛 / 友圈 / 运动记录」之上，加一层有裁判、可回看、
> 公开可讨论的约战玩法。纯趣味，不涉及钱和实物奖励。

---

## 一、玩法（裁判制 1v1）

### 1.1 一次挑战的完整流程

```
① 发起：A 选项目 + 比法 + 期限 + 指定一名教练当主裁判 → 提交
        ↓
② 被挑战者 B 应战 / 拒绝（超时未应战 → 失效）
        ↓
③ 双方各自上传挑战视频（或由教练代传），到截止时间
        ↓
④ 主裁判看视频，判定：
     · 谁胜 / 谁负 / 平局
     · 或标记「视频作弊」（可分别标任一方）
        ↓
⑤ 结果公开：所有会员可看挑战详情、看视频、看判定理由、发表意见
        ↓
⑥ 结算：胜场/连胜/徽章更新；可选发到友圈
```

### 1.2 挑战要素

| 要素 | 说明 |
| --- | --- |
| **项目** | 复用排行榜项目（卧推/深蹲/硬拉/站姿肩推/引体向上） |
| **比法** | 绝对成绩 / 相对体重（P1 先开绝对） |
| **主裁判** | **必选**，从教练列表里指定；教练可看到「待我判决」列表 |
| **期限** | 应战期限 + 视频提交期限（两段） |
| **公开** | 挑战生成后所有会员可见；详情页含视频、判定、评论 |

### 1.3 裁判的权限（核心）

| 能力 | 说明 |
| --- | --- |
| 看全部证据 | 双方视频、成绩、历史记录 |
| 判定结果 | 胜 / 负 / 平，可写一句判定理由（会员可见） |
| 标记作弊 | 标记某一方视频作弊（可写原因），该方直接判负，并在挑战上留「作弊」标记 |
| 代传视频 | 现场由教练拍摄代传（现在力量成绩已能拍视频 + 自动裁切） |
| 改判 | 判定后一段时间内可改判（建议 24h），改判留痕 |

### 1.4 会员能做什么

- 发起挑战（指定裁判）、应战/拒绝、上传自己的视频
- 浏览**所有**挑战（列表 + 详情），看视频、看判定
- 在挑战下**发表意见**（评论），可点赞他人意见
- 自己的评论可删除；管理员可删任意评论

## 二、数据模型（v3 草案）

```sql
-- 挑战主体
create table if not exists challenges (
  id              text primary key,
  challenger      text not null,
  opponent        text not null,
  referee         text not null,              -- 主裁判（教练 openid）
  lift_key        text not null,
  metric          text not null default 'absolute',
  trash_talk      text not null default '',
  status          text not null default 'pending',
      -- pending 待应战 / accepted 已应战 / submitted 双方已交视频
      -- judged 已判定 / declined 已拒绝 / expired 失效 / cancelled 取消
  judge_result    text not null default '',   -- win_challenger / win_opponent / draw
  judge_note      text not null default '',   -- 判定理由（会员可见）
  judged_at       bigint not null default 0,
  expire_at       bigint not null default 0,  -- 应战截止
  submit_by       bigint not null default 0,  -- 视频截止
  created_at      bigint not null default 0,
  finished_at     bigint not null default 0
);

-- 双方提交的视频（一人可多条，至少各一条）
create table if not exists challenge_videos (
  id            text primary key,
  challenge_id  text not null references challenges(id) on delete cascade,
  openid        text not null,               -- 这条视频属于谁（挑战双方之一）
  video_url     text not null,
  video_thumb   text not null default '',
  uploaded_by   text not null default '',    -- 上传人：本人 / 教练
  cheat_flag    boolean not null default false,  -- 裁判标记作弊
  cheat_reason  text not null default '',
  created_at    bigint not null default 0
);

-- 会员发表的意见
create table if not exists challenge_comments (
  id            text primary key,
  challenge_id  text not null references challenges(id) on delete cascade,
  openid        text not null,
  content       text not null,
  like_count    int not null default 0,
  status        text not null default 'normal',  -- normal / hidden（管理员隐藏）
  created_at    bigint not null default 0
);
```

> 挑战成绩仍然写进 `strength_records`（带 `challenge_id` 标记），不搞第二套账；
> 视频走现有 `/api/video`（按管理页设定自动裁切、限制体积）。

### 3.2 教练端

| 页面 | 内容 |

| 判定面板 | 看双方视频 → 判胜负平 / 标作弊 / 写理由 |
| 代传视频 | 现场拍摄上传 |

### 3.3 接口（action）

| `createChallenge` | 会员 | 发起（必须带 referee） |

| `coachList` | 会员 | 选裁判用（已有 listCoaches） |
| `challengeBoard` | 会员 | 战绩榜 / 连胜榜 |

## 四、消息通知方案（你的问题 2）

挑战涉及三方：**发起人、被挑战者、主裁判**。分三层做，从低成本到高成本：

### 层 1：小程序内（零门槛，必做）

| 手段 | 效果 | 实现 |
| --- | --- | --- |
| **tabBar 红点** | 底部「友圈/我的」出现小红点 | `wx.showTabBarRedDot` / `setTabBarBadge` |
| **挑战大厅角标** | 「待我应战 2」「待我判决 3」 | 列表页 tab 上带数字 |
| **首页模块** | 「你有 1 场挑战待应战」「3 场待你判决」 | 复用首页模块机制加一个 `challenge` 模块 |
| **教练工作台** | 「待我判决」入口带红点 | 员工端首页 |

> 局限：用户不打开小程序就看不到。所以需要层 2。

### 层 2：微信订阅消息（真正的"推送到手机"）

原理：用户在**点击某个按钮时**授权一次，之后可以给他发**一条**消息。
现有 `lib/notify.js` 已经支持（`WX_TPL_*` 环境变量配模板 ID），目前 3 个模板都是空的，需要在小程序后台申请。

建议申请 2 个模板：

| 用途 | 触发时机 | 模板字段（示例） |
| --- | --- | --- |
| **挑战通知** | 有人向你发起挑战 / 你的挑战被判定 | 谁发起（thing）、项目（thing）、时间（time）、提示（thing） |
| **裁判待办** | 有新挑战需要你判 / 双方视频已交齐 | 挑战方（thing）、项目（thing）、时间（time）、提示（thing） |

授权时机（关键）：
- 会员**发起挑战**时顺带申请「挑战通知」授权（一次性）
- 会员**应战**时申请授权
- 教练**被指定为裁判**时，在下一次打开小程序/员工工作台时弹一次授权
- 每次授权只能发一条，所以要"省着用"：只发**真正需要动作**的消息（该你了），不发"结果已出"

**限制**：长期订阅（发多条）只对政务/医疗等特定类目开放，健身类只能一次性订阅。所以：
- 每个人每次互动前都要重新授权 → 设计成"点了应战/提交时顺手申请"，用户感知自然
- 如果模板申请不下来（个人主体可选模板有限），就退回层 1 + 层 3

### 层 3：兜底渠道

| 渠道 | 说明 | 成本 |
| --- | --- | --- |
| **分享到微信群** | 挑战详情页做 `onShareAppMessage`，谁都可以分享到群里@对方 | 0 |
| 公众号模板消息 | 需要会员关注公众号并绑定 openid | 中（要运营） |
| 短信 | 通过短信服务商（阿里云/腾讯云）发 | 按条计费 |
| 教练群播报 | 员工工作台每天一条汇总，教练自己转发到会员群 | 0 |

### 我的建议（P1 落地）

1. **先做层 1**（红点 + 角标 + 首页模块），1 天内能完
2. **同时申请「挑战通知」「裁判待办」两个订阅消息模板**，接通层 2（`notify.js` 现成）
3. **分享卡片**当兜底（0 成本，还能带量）
4. 不做短信/公众号（成本与运营收益不匹配）

## 五、时间与状态（待你确认）

```
pending（待应战）──应战──> accepted（已应战）──双方交视频──> submit_ready
   │拒绝 → declined                                │
   └超时 → expired                                 ↓
                                          judged（裁判判定）
```

需要你定：
1. **应战期限**：24h / 72h / 7 天（默认？）
2. **视频提交期限**：应战后再给多久？72h？
3. **裁判判决期限**：视频交齐后多久内必须判？（超时是否提醒管理员？）
4. **裁判能不能拒绝指派**？（建议：能，拒绝后发起人重选，或管理员兜底指派）

## 六、防滥用（有了裁判之后简化很多）

| 风险 | 对策 |
| --- | --- |
| 视频造假 | 裁判标记作弊 → 判负 + 挑战页标记；作弊次数累计，公开可见 |
| 只挑软柿子 | 「以下克上」徽章；被拒冷却 |
| 刷挑战 | 每周发起上限、同对手冷却 |
| 恶意评论 | 评论可被管理员隐藏/删除；被举报 3 次自动隐藏 |
| 裁判不公 | 判定理由公开；管理员可改判（留痕） |

## 七、需要你继续定的（按编号回我）

**A. 裁判**
1. 主裁判必须是教练角色吗？还是管理员也可以？
2. 发起时由发起人指定裁判，被挑战者有没有否决权？
3. 裁判能否拒绝接这个活？拒绝后怎么办（重选 / 管理员兜底）？
4. 判决后多久内可以改判？
5. 判定理由是否对所有会员可见？

**B. 视频**
6. 双方是否**都必须**上传视频，还是一方可免（比如直接认输）？
7. 视频是一段还是可以多段？（建议：每人最多 3 段）
8. 视频用现有管理设定裁切（最长 N 秒 / N MB），还是挑战视频单独放宽？
9. 作弊标记的后果：判负 + 公开标记 + 累计次数，够不够？要不要禁赛一段时间？

**C. 公开与评论**
10. 挑战对谁可见：所有会员 / 仅参与者和教练 / 所有人（含未登录）？
11. 评论要不要先审后发？还是先发后管（管理员删除）？
12. 评论要不要点赞？
13. 挑战要不要也能发到友圈（复用现有分享）？

**D. 流程与通知**
14. 应战期限 / 视频截止 / 裁判判决期限分别多久？
15. 通知渠道：红点 + 订阅消息（需申请模板）+ 分享卡片，这个组合可以吗？
16. 每人同时最多几场挑战？

**E. 范围**
17. P1 做到什么程度：只做「发起→应战→视频→裁判判定→公开详情」，评论和挑战榜放 P2？
18. 徽章要不要（首胜/三连/以下克上/全项目）？

## 八、建议的排期（按裁判制）

| 期次 | 内容 | 预估 |
| --- | --- | --- |
| **P1** | 挑战表 + 视频表、发起（选裁判）/应战/上传视频、教练判定面板（胜负平+作弊标记）、公开详情页、红点 | 3–4 天 |
| **P2** | 评论 + 点赞、挑战榜、徽章、订阅消息接通、分享卡片 | 2–3 天 |
| **P3** | 公开悬赏挑战、运动记录类挑战、赛季 | 看热度 |

> 裁判制比原来自动结算版本多了「裁判工作台 + 判定留痕」，P1 从 2–3 天变成 3–4 天，
> 但换来的是**结果可信、争议可追溯**，值得做。

## 九、不做什么

- 不做金钱 / 实物赌注
- 不做自动判胜负（按你的规则，结果由裁判拍板）
- 不做实时直播（用视频留档 + 评论互动）
- 不新增第二套成绩数据（挑战成绩仍写 strength_records）

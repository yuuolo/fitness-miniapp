# 会员挑战功能 · 设计方案

> 目标：在现有的「身体数据 / 力量排行 / 竞赛 / 友圈」之上，加一层**人对人的轻量互动**，
> 让会员之间有借口互相约练、互相监督，产生复访和话题。
> 原则：**复用现有项目与成绩体系**，不另起一套数据；纯趣味，不涉及钱和实物奖励。

---

## 一、玩法设计

### 1.1 三种挑战形态（分三期做）

| 形态 | 说明 | 期次 |
| --- | --- | --- |
| **1v1 指定挑战** | A 指定 B，选一个项目 + 比法 + 期限；B 应战或拒绝 | P1 |
| **公开挑战（悬赏）** | A 公开挂一个成绩，任何会员可以来"打擂"，先到先得/限 3 人 | P3 |
| **团队/赛季赛** | 分队累计积分、月度赛季榜 | P3 |

P1 只做 1v1，先把闭环跑通。

### 1.2 挑战要素

发起时选 4 项：

1. **项目**：复用排行榜项目（卧推 / 深蹲 / 硬拉 / 站姿肩推 / 引体向上），管理员在管理端加的项目自动可选
2. **比法**（二选一）
   - 绝对成绩：比重量 / 次数
   - 相对体重：成绩 ÷ 体重（小体重不吃亏，同时用「参与相对体重排行」开关的同学才有体重数据做分母）
3. **期限**：24h / 72h（默认）/ 7 天
4. **一句垃圾话**（最多 20 字，可选）：出现在对方的挑战卡片上，增加趣味

### 1.3 流程与状态机

```
        ┌──────────── 发起人取消（未应战时） ────────────┐
        ↓                                               │
   [待应战] ──应战──> [进行中] ──双方都交成绩──> [已结算：胜/负/平]
      │  │
      │  └──拒绝──> [已拒绝]（发起人可再发，但同对手 7 天冷却）
      └──超时未应战──> [已失效]
```

- 应战后 48 小时内双方各自提交成绩，超时未交的一方判负
- 双方都不交 → 判「流局」，不计胜负
- 结算后进入双方的历史记录，并可一键发到友圈

### 1.4 成绩怎么来（两条路，都走现有成绩体系）

| 方式 | 说明 | 实现 |
| --- | --- | --- |
| **用已有最好成绩** | 一键应战，拿自己该项目历史最好成绩 | 读 `members.best_lift[项目]` |
| **现场练一次** | 教练现场录入（可拍视频），成绩更硬 | 复用 `saveStrength`，带 `challengeId` 标记 |

设计上先做「已有最好成绩」，**现场录入作为 P1 的可选项**（教练端已具备录成绩能力，只是多传一个 challengeId）。

### 1.5 输赢与趣味奖励（纯虚拟）

- **胜负**：分数高者胜；相同为平
- **统计**：胜场 / 负场 / 胜率 / **连胜**
- **徽章**（自动颁发，展示在资料页）
  - 首胜（第一次赢）
  - 三连 / 五连
  - 「以下克上」：赢了项目排名比自己高的人
  - 「全项目挑战者」：五个项目各赢过一次
- **挑战榜**：本周胜场榜、当前连胜榜（复用排行榜页的 tab 结构）

## 二、数据模型

新增两张表，全部**复用现有成绩表**作为真实成绩来源，挑战表只存"约战关系 + 结算快照"。

```sql
-- 挑战（一条 = 一次约战）
create table if not exists challenges (
  id              text primary key,
  challenger      text not null,              -- 发起人 openid
  challenger_name text not null default '',
  opponent        text not null,              -- 被挑战者 openid
  opponent_name   text not null default '',
  lift_key        text not null,              -- 项目 key，来自 lift_items
  lift_name       text not null default '',
  unit            text not null default 'kg',
  metric          text not null default 'absolute',   -- absolute / relative
  trash_talk      text not null default '',          -- 垃圾话
  status          text not null default 'pending',   -- pending/accepted/finished/declined/expired/cancelled
  result          text not null default '',          -- win_challenger / win_opponent / draw / void
  expire_at       bigint not null default 0,         -- 应战截止
  submit_by       bigint not null default 0,         -- 应战后提交成绩截止
  created_at      bigint not null default 0,
  finished_at     bigint not null default 0
);
create index if not exists idx_challenges_opponent on challenges (opponent, status);
create index if not exists idx_challenges_challenger on challenges (challenger, status);

-- 挑战成绩（一场挑战最多两条：双方各一条）
create table if not exists challenge_entries (
  id            text primary key,
  challenge_id  text not null references challenges(id) on delete cascade,
  openid        text not null,
  value         numeric(8,2) not null default 0,   -- 该项目算出的成绩（1RM / 次数）
  relative      numeric(8,2) not null default 0,   -- 相对体重（比法为 relative 时用）
  weight        numeric(6,2) not null default 0,
  source        text not null default 'best',      -- best（历史最好）/ staff（现场录入）
  by_openid     text not null default '',          -- 谁录的（现场录入时是教练）
  video_url     text not null default '',
  created_at    bigint not null default 0
);
create unique index if not exists uq_challenge_entry on challenge_entries (challenge_id, openid);
```

> 现场录入时，同时往 `strength_records` 插一条（`operator` 记教练），
> 这样挑战成绩**天然进入排行榜**，不需要两套数据。

## 三、接口设计（action 列表）

沿用 `/api` 的 `{action, data}` 协议，新增 6 个 action：

| action | 权限 | 说明 |
| --- | --- | --- |
| `challengeList` | 会员 | 挑战大厅：`tab=incoming/outgoing/active/history` |
| `challengeDetail` | 参与者或员工 | 详情 + 倒计时 + 双方成绩 + 结算结果 |
| `createChallenge` | 会员 | 发起：对手、项目、比法、期限、垃圾话 |
| `respondChallenge` | 被挑战者 | `accept` / `decline` |
| `submitChallengeScore` | 本人或教练 | 用最好成绩 / 现场录入（带 weight+reps+video） |
| `challengeBoard` | 会员 | 周胜场榜 / 连胜榜 / 我的战绩 |

## 四、页面设计（小程序）

| 页面 | 内容 |
| --- | --- |
| `pages/challenges/list` 挑战大厅 | 顶部：我收到的（红点数量）/ 进行中 / 我发起的 / 历史 4 个 tab；卡片显示对手、项目、比分、倒计时 |
| `pages/challenges/new` 发起挑战 | 选对手（从会员列表 / 排行榜点人发起）→ 选项目 → 选比法 → 选期限 → 填垃圾话 → 发送 |
| `pages/challenges/detail` 挑战详情 | 双方头像+成绩+比法、倒计时、应战/拒绝/提交按钮、结果页可「发到友圈」 |
| `pages/challenges/leader` 挑战榜 | 本周胜场 / 当前连胜 / 我的战绩 |

**入口**：
- 首页快捷入口加一格「发起挑战」（复用现有 6 种模块里的 `quick`，或做成新模块类型 `challenge`——建议**加一个首页模块类型**，管理员可拖到任意位置）
- 排行榜点某人「发起挑战」
- 会员资料页「挑战 TA」
- 「我的」加一行「我的挑战」

**教练端**（`pages/staff/challenges/*`）：
- 查看所有进行中的挑战
- 代会员录入挑战成绩（可拍视频）
- 取消违规挑战

## 五、与现有功能的一致性

| 现有能力 | 复用方式 |
| --- | --- |
| 功能开关 | 新增第 5 个开关 `challenge`（管理页可整体关闭），关闭后入口隐藏、接口拦截 |
| 排行榜项目 | 直接读 `lift_items`，管理员新增项目自动可选 |
| 相对体重比法 | 复用排行榜的相对体重逻辑与「参与相对体重排行」开关 |
| 成绩录入 | 复用 `saveStrength`，只多传 challengeId，成绩照常进排行榜 |
| 分享 | 结算后生成一条友圈动态（`type=challenge`）或直接转发挑战详情页 |
| 会员资料 | 资料页展示"挑战战绩 + 徽章" |
| 提醒 | P1 不做订阅消息（个人主体模板受限），靠页面红点 + 友圈动态；P2 视模板情况再补 |

**动态评分衔接**：挑战成绩进 `strength_records`，评分本来就是实时算的（1.5.18 之后），
所以挑战赢了会立刻体现在身体评分和六边形能力图上——天然联动，不用额外处理。

## 六、防滥用与公平

| 风险 | 对策 |
| --- | --- |
| 刷挑战刷胜场 | 每周最多发起 5 次；同一对手 7 天内只能挑战 1 次 |
| 只挑软柿子 | 徽章「以下克上」只奖励赢排名更高的人；另设「被拒绝 3 次后冷却 24h」 |
| 自报成绩造假 | 默认用历史最好成绩（无法伪造）；现场录入必须教练操作，可附视频 |
| 用挑战刷排行榜 | 挑战成绩与普通成绩同源，本身不额外加权；另外限制同一项目每天只算 1 条挑战成绩 |
| 骚扰 | 被拒绝后不能立刻再发；管理员可取消任意挑战；后续可加「不接受某人挑战」黑名单 |
| 拖延 | 应战 72h 超时失效；应战后 48h 未交成绩判负 |

## 七、分期与工作量

| 期次 | 内容 | 预估 |
| --- | --- | --- |
| **P1** | 1v1 挑战全流程（发起/应战/提交/结算/列表/详情）+ 功能开关 + 首页模块 + 通知红点 | 2–3 天 |
| **P2** | 挑战榜 + 战绩与徽章 + 结算后发友圈 + 教练端代录 | 1–2 天 |
| **P3** | 公开悬赏挑战、团队/赛季赛、订阅消息提醒 | 2–3 天 |

P1 完成即可上线，P2 补齐趣味性，P3 看使用情况再定。

## 九、需要你拍板的 6 个点

1. **挑战成绩算不算进排行榜？**
   建议：算（同一套数据，不打两套账），但同一项目每天最多计 1 条挑战成绩，避免刷榜。
2. **现场录入要不要强制教练？**
   建议：P1 允许"用我的最好成绩"直接应战（零成本），现场录入必须教练；如果你希望所有成绩都教练见证，那就只保留现场录入。
3. **比法默认哪种？**
   建议：默认绝对成绩（直观），发起时可选相对体重。
4. **期限默认多长？**
   建议：应战 72 小时、提交 48 小时。
5. **要不要"公开悬赏挑战"（任何人对任何人）？**
   建议：P3 再做，P1 先控制在小范围熟人之间，避免陌生人骚扰。
6. **徽章要不要出现在会员资料页（别人能看）？**
   建议：要，正好利用 1.4.x 已放开的公开资料页。

## 十、不做什么（明确排除）

- 不做金钱/实物赌注（合规风险）
- 不做实时语音/视频对战（成本太高，用视频留档即可）
- 不做复杂的排位分/ELO（对健身会员来说太重，胜场 + 连胜足够）
- 不新增第二套成绩数据（全部挂在 strength_records 上）

# 运动数据对接方案（手机 / 手环 / 手表 / 运动 App）

> 现状：会员可以在小程序里自己记录运动，教练也能代录；后台有运动记录管理。
> 本文是「自动同步用户设备数据」的落地方案，按**可行性 / 成本 / 周期**排序。

---

## 一、先明确：数据模型是统一的

不管数据从哪来，最终都落成同一条活动记录（`activity_records`）：

| 字段 | 说明 |
| --- | --- |
| `openid` | 会员 |
| `date` | 运动日期（YYYY-MM-DD，北京时间） |
| `type` | `walk` / `run` / `cycling` / `swim` / `strength` / `class` / `other` |
| `steps` | 步数 |
| `distance` | 公里 |
| `duration` | 分钟 |
| `calories` | 千卡 |
| `avgHr` | 平均心率 |
| `source` | 来源，如 `self` / `staff` / `wechat` / `apple_health` / `garmin` / `strava` |
| `externalId` | 数据源里的唯一 ID，用来去重（**关键**） |

**去重规则**：有 `externalId` 时按「会员 + 来源 + 外部 ID」唯一；同一份数据重复同步只会更新，不会堆积。

> 已有能力：后台「运动记录」模块、批量导入接口 `importActivity`（见第五节）。

## 二、五条接入路径（按推荐顺序）

### 路径 A：微信运动（P0，最省事，建议先做）

- **能拿到**：当天步数（`wx.getWeRunData` → 后端解密 `encryptedData`，得到最近 30 天的步数）
- **拿不到**：距离、心率、卡路里（微信不提供）
- **成本**：0，不需要企业资质，不需要原生 App
- **限制**：会员必须在小程序里授权「微信运动」；只能拿到步数
- **落地**：小程序点「同步微信运动」→ 后端解密 → 按日期批量 upsert `type=walk, source=wechat, steps=N`

### 路径 B：管理员批量导入 / 手动录入（P0，已在做）

- 会员自己录、教练代录（已完成）
- 后台批量导入：**接口已就绪**（`importActivity`），可先用「导出手机健康数据 → 转 JSON → 导入」的过渡方案
- 适合：少量会员、教练帮忙代录、从其它表格迁移历史数据

### 路径 C：运动 App 开放平台（P1，性价比最高的"真数据"）

| App | 能力 | 门槛 |
| --- | --- | --- |
| **Strava** | 跑步/骑行/游泳，距离、时长、心率、轨迹 | 免费注册 API 应用，OAuth2，个人可用（未审核限 1 个测试账号，正式需申请提额） |
| **COROS / 高驰** | 跑步、骑行、游泳 | 需商务合作 |
| **Keep / 咕咚 / 悦跑圈** | 跑步、骑行 | 需商务合作，个人难拿 |
| **Garmin** | 全运动类型、心率、睡眠 | 需申请 Garmin Health / Connect API 合作伙伴，审核 4–8 周 |

**推荐先接 Strava**：OAuth2 + `GET /athlete/activities`，一个后端定时任务就能拉全量，字段和我们模型几乎一一对应。

### 路径 D：手机系统健康数据（P2，需要原生能力）

- **iOS HealthKit / Android Health Connect**：**小程序无法直接读**，必须有一个原生 App（或 Web 端 + Health Connect Web 授权，Android 侧较新）做中转
- 折中方案：用一个「健康数据导出 App / 第三方聚合服务」把数据转成 JSON 推到我们的导入接口
- **第三方聚合服务**（Terra、Vital、Rook）：一次接入覆盖 Apple Health / Garmin / Fitbit / Oura / 华为等，**按用户数收费**（通常 0.5–2 美元/用户/月），适合后期规模化

### 路径 E：手环/手表厂商 SDK（P3，门槛最高）

华为运动健康、小米运动健康、OPPO/vivo 健康、三星 Health：

- 一律要求**企业开发者资质 + 厂商审核**（2–6 周），且多数只对原生 App 开放
- 结论：现阶段不碰，除非门店规模上来、且明确要「会员自动同步」这个卖点

## 三、推荐落地节奏

| 阶段 | 做什么 | 周期 | 收益 |
| --- | --- | --- | --- |
| **P0（现在）** | ①会员自己录（已完成）②教练代录（已完成）③后台管理与删除（已完成）④批量导入接口（已完成） | — | 立刻可用 |
| **P0+（1 天）** | 微信运动步数一键同步 | 1 天 | 零成本、人人都能用，回访理由 |
| **P1（2–3 天）** | Strava OAuth 接入 + 每日定时拉取 | 2–3 天 | 真数据（跑步/骑行/游泳），适合爱运动的核心会员 |

| **P2（1–2 周）** | 原生中转 App 或第三方聚合（Terra/Vital） | 1–2 周 | 覆盖 Apple Health / 华为 / 小米 / Garmin |
| **P3** | 厂商 SDK 直连 | 1–2 月 | 体验最好，成本最高 |

## 四、绑定与授权流程（所有路径通用）

```
会员在小程序 → 「连接设备/App」 → 生成一次性绑定码（或跳 OAuth 授权页）
        ↓
第三方/设备返回授权 → 后端回调，用 state / 绑定码 把「外部账号 ID」映射到 openid
        ↓
定时任务（或 webhook）拉取新数据 → 调 importActivity（带 source + externalId 去重）
        ↓
会员在小程序「运动记录」里看到，也可在「我的」里断开授权
```

要点：
- **绑定码一次性、5 分钟有效**，绑定关系存 `member_devices(openid, source, external_account, token, created_at)`
- 授权可随时断开，断开后删除 token（历史记录保留）
- 隐私：只取运动相关的字段，不取原始轨迹/位置；《个人信息保护法》要求告知用途与保存期限

## 五、批量导入接口（已实现，可直接对接）

`POST /api`，`action: importActivity`，权限：管理员

```json
{
  "action": "importActivity",
  "data": {
    "items": [
      {
        "openid": "会员 openid",
        "date": "2026-11-16",
        "type": "run",
        "distance": 5.2,
        "duration": 32,
        "calories": 320,
        "avgHr": 148,
        "source": "strava",
        "externalId": "1234567890"
      }
    ]
  }
}
```

返回：`{ imported, updated, skipped, total }`

- `externalId` 相同 → 走更新，不会重复
- 一次最多 500 条，超了分批
- 小程序/手环/任何服务只要能把数据转成这个格式，就能接进来

## 六、成本与风险一览

| 方案 | 成本 | 周期 | 数据完整度 | 风险 |
| --- | --- | --- | --- | --- |
| 会员自己录 / 教练代录 | 0 | 已完成 | 中（靠自觉） | 数据可能不准 |
| 微信运动 | 0 | 1 天 | 低（只有步数） | 需授权，无距离/心率 |
| Strava | 0 | 2–3 天 | 高（跑步/骑行/游泳） | 只覆盖用 Strava 的人 |
| 截图 OCR | 0 | 2 天 | 中 | 识别错误需人工确认 |
| 第三方聚合（Terra/Vital） | 按用户计费 | 1–2 周 | 很高（覆盖主流设备） | 长期成本、数据出境合规 |
| 原生 App + HealthKit | 开发成本高 | 1–2 周 | 很高 | 需上架 App Store |
| 厂商 SDK | 审核成本 | 1–2 月 | 很高 | 资质门槛 |

---

## 七、我的建议

1. **先做微信运动步数同步**（1 天，免费，人人可用）——这是投入产出比最高的一步
2. **再接 Strava**（2–3 天，免费）——让爱运动的核心会员有"真数据"可晒
3. **截图 OCR 当兜底**（2 天）——覆盖所有品牌，不用等任何合作
4. 等会员规模上来（比如 50+ 活跃），再评估付费聚合或原生 App

## 八、需要产品决策的点

1. 会员自动同步的数据，要不要和手动录入**分开展示**（标「设备同步」）？建议要，便于判断可信度
2. 同一份数据既有设备同步又有手动录入时，**以谁为准**？建议：设备优先，手动录入的时间段重叠时提示
3. 是否允许会员**关闭自动同步**？建议允许（隐私）
4. 步数是否参与排行榜/竞赛？建议暂不参与，只做展示与趋势
